# 软件文档编写要求

## 内容边界

1. 正文只描述**当前版本**的事实、能力、行为、限制和操作方式。选项说明必须足够详尽，使用户仅凭手册即可理解并使用本程序，详细程度可参考 ORCA、Gaussian 等软件手册。
2. 不要将历史包袱、旧版本兼容原因、过去的实现方式、演进过程或设计妥协散落在正文中。相关内容只能放在以下位置之一：
   - Release Notes
   - 更新历史
   - 版本变更说明
   - 迁移说明

   除非任务明确要求，否则正文不要出现：
   - “这是按照当前版本代码……”
   - “为了兼容旧版本……”
   - “历史原因……”
   - “沿用旧逻辑……”
   - “此前”“原先”“过去”等版本回顾表述
   - “因为老用户习惯……”
   - “出于向后兼容考虑……”
3. 用户手册不得大篇幅讨论普通用户无需了解的代码职责边界、内部结构或实现细节。

## 内容要求

优先写清楚以下内容：

- 这是什么
- 适用于什么场景
- 如何使用
- 输入和输出是什么
- 有哪些明确限制
- 用户应如何理解当前行为

所有表述应以产品事实和官方说明为中心。输入信息不足时，应基于已有信息采用最稳妥的表述，并在文档正文之外列明信息缺口。

## 结构要求

默认使用清晰的文档结构，例如：

- 概述
- 功能说明
- 使用方式
- 参数与配置
- 输入文件

## 排版要求

Noto Serif 字体不包含 `→` 字符，应避免使用该符号。
